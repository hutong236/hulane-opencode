The user explicitly approves: $ARGUMENTS. Act as Primary Agent Orchestrator and use `hulane-control` MCP tools for every state/authority action. Call `hulane_status` with GitHub refresh when resuming across sessions or when local state is stale or suspect; if this session just created/synced the Work Item, the revision-guarded local state is enough. Then `hulane_transition(approve_requirement, actor=human:<identity>)` to record Gate A — this command remains the human override channel for the Gate A whitelist stops (high risk, Planner-reported requirement ambiguity, explicit user pause) and records `approval_source="issue_stop"`; the same-turn lanes from `/hulane_dev` (default `auto_intake` with actor orchestrator, or `pre_authorized` with actor human:<identity> on explicit approval wording) are applied there without this command and never require it. Resolve and fetch the current default branch, then call `hulane_worktree_create` with explicit base `origin/<default-branch>`; pin Planner completion, Coder, Tester, and Reviewer to the returned path. For spec_sync_required items, instruct Coder to park the decision history at `openspec/changes/archive/<ID>/` and complete the delta-to-main-spec smart merge inside the PR (only touched capabilities), and hand the delta scenarios to Tester and Reviewer. Record every milestone with `hulane_transition`; never hand-edit state. After the Coder completes, dispatch Tester and Reviewer in the same round — Reviewer is read-only, so parallel dispatch does not violate the single-writer rule; proceed only when both results are in (Tester passed + Reviewer approved), and on any failure return to Coder and re-dispatch both. Stop when the three-round rework budget blocks. After reviewer approval commit only related files, call `hulane_authorize(git-push)` and use the returned token for exactly one push from the recorded worktree cwd. Create a PR with `Refs #issue`, record `pr_created`, then call `hulane_verify_pr_checks`; never submit `checks_passed` through the generic transition tool. While the check run is still in progress, never block or poll in the foreground: start one background `gh run watch <run-id> --exit-status --interval 30` Bash task, tell the user the checks are running, and end the turn; the completion notification — or a later resume finding the item `pr_checking`, which runs one `gh run list` query and re-arms the watch while the run is still going — continues with verification and the merge gate. Public repositories require GitHub-enforced checks. Private repositories without paid branch protection use the exact-SHA control-plane guard. High risk stops at waiting_human_merge for `/hulane_merge_approve`; low/medium risk under either guard mode proceeds with one merge. Every merge command must include `--match-head-commit <persisted-pr-head-sha>` and needs no token — the guard state-verifies merges from the `merging` state. Verify merged SHA, record pr_merged, then split by the persisted delivery policy: when delivery_required is false and skip_allowed is true, immediately record `policy_skip` (actor orchestrator, evidence citing the Gate A approval record: Issue number, approval_source, delivery_reason), pass the spec gate — for spec_sync_required items call `hulane_record_specs_synced(specs_commit_sha=merged_sha, spec_delta_dir=openspec/changes/archive/<ID>)`, which validates the merged tree's `openspec/specs/` structure before recording; exempt/small/grandfathered items skip it — then close the exact Issue once (state-verified, no token), record issue_closed, housekeep the merged worktree — plain `git worktree remove <worktree_path>` (never `--force`) then `git branch -d <branch>` from the managed repository — and report Done — no human stop; otherwise STOP at waiting_tag_confirm for tag confirmation. Do not invoke the legacy state CLI or bypass MCP.
